# RGW C 编程核心规则

## 1. API 命名规范

**规则 1.1:** 所有函数使用统一前缀：`rgw_string_*`、`rgw_buffer_*`、`rgw_hex_*`、`rgw_b64_*`

## 2. 头文件包含

**规则 2.1:** 使用相关功能时必须包含对应头文件（如 `rgw_cmemory.h` 包含内存函数）

## 3. 内存管理

**规则 3.1:** 每个 `rgw_c_alloc`/`malloc` 必须有对应的 `rgw_c_free`/`free`，禁止混用
**规则 3.2:** 避免双重释放：手动释放后确保不再被第三方回调释放
**规则 3.3:** 释放后将指针置为 NULL

## 4. 数据结构

**规则 4.1:** 容器必须支持动态扩容（容量满时翻倍扩容）
**规则 4.2:** 优先使用 `c_common` 现有数据结构，禁止重复造轮子

## 5. 宏定义

**规则 5.1:** 宏内部变量使用 `int` 类型兼容所有整数类型
**规则 5.2:** 明确宏是语句而非表达式，不能将宏结果赋值给变量

## 6. 字符串处理

**规则 6.1:** `tolower`/`toupper` 参数必须先转换为 `unsigned char`
**规则 6.2:** 字符串转数值必须处理负数和边界溢出
**规则 6.3:** 偏移量和大小参数必须检查负数

## 7. 递归函数

**规则 7.1:** 递归函数必须设置深度限制，防止栈溢出
**规则 7.2:** 递归深度限制应合理（如 1000 层），并通过错误码返回
**规则 7.3:** 递归函数的错误处理必须完整，确保所有路径都能正确清理资源

## 8. 错误处理

**规则 8.1:** 所有错误码必须在头文件中明确定义
**规则 8.2:** 错误处理路径必须完整，确保所有资源都能被正确释放
**规则 8.3:** 函数返回错误时，必须清理已分配的所有资源
**规则 8.4:** 错误码应具有明确的语义，便于调用者理解

## 9. 测试验证

**规则 9.1:** 测试必须验证返回值、边界条件和错误处理路径
**规则 9.2:** 每次修改后必须编译并运行所有测试
**规则 9.3:** 测试应覆盖递归深度限制等边界情况

## 10. 代码提交前检查

- 内存分配与释放是否配对
- 是否存在双重释放风险
- 容器是否支持扩容
- 宏类型和用法是否正确
- 指针是否已初始化
- 边界条件是否处理
- 递归函数是否有深度限制
- 错误处理路径是否完整
- 所有错误码是否在头文件中定义
- 是否包含所有必要的头文件
